# 服装企业数字化大脑 Agent — 完整路线图

本文档汇总四大里程碑（Milestones）及所有执行议题（Issues），便于排期与验收。

---

## Milestone 1：基础设施与数据「血液」打通

**目标：** 让 Agent 能够「看见」公司库存实时状态，并「听见」市场流行趋势。

| Issue | 标题 | 说明 |
|-------|------|------|
| [1.1](issues/issue-1.1-erp-oms集成.md) | 内部 ERP/OMS 接口集成 | 开发标准 API 插件，实时查询 SKU 销量、在途库存、退货率 |
| [1.2](issues/issue-1.2-外部趋势抓取.md) | 外部趋势抓取工具（Scraper） | 集成 TikTok/小红书/Instagram 热门标签爬取，获取当季流行元素（如「多巴胺穿搭」「静奢风」） |
| [1.3](issues/issue-1.3-商品多维标签化.md) | 商品多维标签化（Tagging） | 用多模态大模型（如 Gemini 1.5 Pro）对图库商品打标签（领型、材质、风格、颜色），建立结构化索引 |

---

## Milestone 2：选品 Agent — 从「直觉」到「预测」

**目标：** 基于市场趋势与历史表现，推荐下一季爆款或补位款。

| Issue | 标题 | 说明 |
|-------|------|------|
| [2.1](issues/issue-2.1-流行趋势映射.md) | 流行趋势映射逻辑 | 编写 Prompt 使 Agent 将社媒热点转化为具体商品需求（例：社媒「美拉德」热度上升 → 建议增加棕色系裙装选品） |
| [2.2](issues/issue-2.2-竞品差异化分析.md) | 竞品差异化分析（Gap Analysis） | Agent 自动对比竞品上新速度与价格区间，识别己方产品线缺位 |
| [2.3](issues/issue-2.3-首单定量策略.md) | 首单定量策略建议 | 根据选品「风险等级」自动给出首批下单量（MOQ）建议，防止首单盲目铺货 |

---

## Milestone 3：库存管理 Agent — 效率与流转

**目标：** 自动预警断货风险，智能处理呆滞库存。

| Issue | 标题 | 说明 |
|-------|------|------|
| [3.1](issues/issue-3.1-动态库存预警.md) | 动态库存预警系统（Alerting） | 当「剩余库存 / 日均销量 < 补货周期」时，Agent 自动推送到业务员企业微信 |
| [3.2](issues/issue-3.2-滞销品清理决策.md) | 滞销品清理决策树 | 定期扫描：库龄 > 60 天且转化率 < 1% 的商品，自动给出「满减」「直播间秒杀」或「跨仓调拨」方案 |
| [3.3](issues/issue-3.3-智能补货计算器.md) | 智能补货计算器 | 集成 Code Interpreter，计算最优订货量（EOQ），考虑季节性衰减系数 |

---

## Milestone 4：销量回顾 Agent — 闭环归因与策略进化

**目标：** 总结过去，并把教训自动喂给选品 Agent。

| Issue | 标题 | 说明 |
|-------|------|------|
| [4.1](issues/issue-4.1-多维度销售复盘看板.md) | 多维度销售复盘看板 | 自动生成周报/月报，分析各渠道（直播、私域、货架）贡献度 |
| [4.2](issues/issue-4.2-退货率深度归因.md) | 退货率深度归因 | 分析评价语义（如「色差大」「偏小」），反馈选品与质检 |
| [4.3](issues/issue-4.3-策略迭代反馈环.md) | 策略迭代反馈环 | 将本季度「避雷点」（如某面料易皱导致高退货）存入 Agent 长期记忆（Memory），下一轮选品时自动拦截类似款式 |

## 项目执行优先级建议表

| 优先级 | 任务模块 | 核心价值 | 建议周期 |
|--------|----------|----------|----------|
| **P0（必做）** | 内部数据集成 + 销量回顾 | 替代人工周报，看清生意现状 | Week 1–2 |
| **P1（提效）** | 库存预警 + 动态补货 | 直接降低断货造成的损失 | Week 3–4 |
| **P2（进阶）** | 趋势选品 + 竞品监控 | 提高爆款概率，解决卖什么的问题 | Week 5–8 |

## 与 GitHub/GitLab Issues 的对应

若使用 GitHub 或 GitLab，建议：

1. 在仓库中创建 4 个 **Milestone**：M1、M2、M3、M4。
2. 将上述每个 Issue 建为一条 **Issue**，描述从 `docs/issues/issue-*.md` 复制，并归属到对应 Milestone。
3. 在 Issue 标签中可增加：`p0` / `p1` / `p2`、`数据层` / `选品` / `库存` / `复盘` 等，便于筛选。

这样代码与需求文档、议题追踪可统一在本仓库内完成。
